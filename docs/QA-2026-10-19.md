# Laporan Pengujian Website MIS Hayatul Islamiyah Cinangka

Tanggal: 19 Oktober 2026. Lingkungan: Node.js 24, SQLite lokal, Chrome headless pada Windows. Pengujian browser menggunakan database sementara terpisah dari database sekolah. Pengujian ini tidak mengakses atau memigrasikan data ke Supabase dan tidak mengubah website online.

## Hasil akhir

- Build berhasil: 11 halaman.
- 11 kelompok pengujian otomatis API, keamanan, penyimpanan, dan build lulus.
- 44 kombinasi halaman/viewport lulus: 11 halaman pada lebar 320, 390, 768, dan 1366 piksel.
- Tidak ditemukan overflow horizontal atau gambar lokal rusak setelah foto yang terlihat digulir dan dimuat.
- 7 alur browser lulus; tidak ada exception JavaScript atau respons gagal internal pada hasil akhir, di luar simulasi putus koneksi yang memang disengaja.

## Temuan yang diperbaiki

1. Tanggal kalender tidak valid seperti 31 Februari sebelumnya lolos karena JavaScript menormalkan tanggal tersebut. Validasi sekarang membandingkan tanggal asli dengan hasil ISO dan menolak tahun sebelum 1900.
2. Nomor WhatsApp yang hanya berisi tanda hubung bisa lolos regex lama. Server kini memeriksa digit nomor Indonesia setelah pemisah dinormalisasi.
3. Cookie admin yang disalin tetap dapat dipakai setelah logout. Sesi sekarang memiliki nonce acak dan catatan server yang dicabut saat logout; perubahan kata sandi/secret juga membatalkan sesi lama.
4. Percobaan login salah sebelumnya tidak dibatasi di server lokal. Sekarang dibatasi 10 kegagalan per alamat IP selama 15 menit per proses, dengan respons 429 dan Retry-After. Rate limit function Netlify tetap terpisah.
5. JSON rusak, null, atau array menghasilkan error server atau bentuk input yang tidak sesuai. Sekarang ditolak dengan 400.
6. Mutasi konten tanpa ID atau dengan ID tidak dikenal mengembalikan sukses semu. Sekarang mengembalikan 400/404.
7. Origin permintaan ke 127.0.0.1 berbeda dari URL localhost yang dibuat server; login dan PPDB ditolak 403. Server lokal kini mempertahankan host permintaan dan meneruskan IP koneksi ke handler.
8. Saat offline, kegagalan API sekaligus seed.json menghentikan modul dashboard. Shell kini tetap terbuka dan menampilkan status Tidak terhubung, tanpa menawarkan pengeditan offline.
9. Ikon WhatsApp belum tersedia di cache PWA. Aset pendukung PWA sudah ditambahkan ke cache versi baru.
10. Halaman Profil dan Kontak sebelumnya tidak memiliki H1. Judul utama keduanya diperbaiki pada proses build.

## Batas verifikasi

- Tidak ada deploy produksi, Git push, atau pengujian backend Netlify/Postgres yang berjalan di cloud pada pengujian ini.
- Browser memakai database QA dan konten contoh; seluruh data uji tidak ditulis ke database sekolah. Database lokal sekolah hanya diperiksa integritas dan jumlah record secara read-only.
- Pengujian browser memblokir layanan eksternal agar Google Maps dan YouTube tidak memperlambat atau mengubah hasil tes internal. Pembuatan URL thumbnail dan tautan YouTube diuji; ketersediaan video nyata dan pemuatan peta melalui internet belum diverifikasi.
- Pengujian memakai Chrome dengan viewport berbeda, bukan perangkat Android/iOS fisik. Pemasangan aplikasi melalui prompt OS belum diuji; manifest, cache, dan pembukaan shell offline sudah diuji.
- Belum ada audit aksesibilitas penuh dengan pembaca layar, penetration test independen, uji beban produksi, atau uji batas ukuran total seluruh koleksi. Angka lulus di atas berlaku untuk skenario yang diuji.

## Sebelum migrasi ke Supabase

1. Cadangkan `.data/school.sqlite`, file assets, dan seed konten terlebih dahulu. Sebagian konten awal berasal dari `src/seed.mjs`, bukan row database. Tombstone `deleted` menentukan konten seed yang disembunyikan; migrasi harus menggabungkan keduanya agar konten yang dihapus tidak muncul lagi.
2. Gunakan Supabase Auth untuk akun admin dan role yang diverifikasi di server. Sesi lokal sekarang adalah sesi aplikasi khusus dan tidak boleh disalin sebagai sesi Supabase. Tabel/record sesi lama tidak perlu diimpor.
3. Terapkan RLS: publik hanya membaca konten publik dan artikel berstatus terbit, pendaftar hanya dapat dikirim melalui jalur tervalidasi, data pendaftar hanya dapat dibaca/diubah admin. Uji kebijakan memakai anon dan admin secara terpisah.
4. Pisahkan entitas pendaftar, artikel, program, ekstrakurikuler, fasilitas, album/foto, video, dan pengaturan. Pertahankan ID dan hubungan album/foto; pastikan sampul, urutan foto, tanggal artikel, status draf, serta status pendaftaran ikut dipindahkan.
5. Pindahkan gambar data URL/base64 ke Supabase Storage. Saat ini gambar bisa tersimpan sebagai string besar dalam JSON. Gunakan URL/path objek, validasi tipe/ukuran, kebijakan akses bucket, dan penghapusan berkas yang sesuai.
6. Pindahkan pembatasan percobaan login dan spam pendaftaran ke mekanisme yang konsisten lintas instance. Batas lokal berbasis memori bukan counter terdistribusi.
7. Ulangi pengujian yang sama pada staging Supabase, termasuk RLS, unggah foto, draft visibility, PPDB, pencabutan sesi, rollback data, dan akses perangkat berbeda. Lakukan cutover setelah hasil data dan perilaku sudah cocok.

Kesimpulan: fungsi lokal yang tercakup sudah lulus pengujian setelah perbaikan. Integrasi Supabase belum diterapkan atau divalidasi; keamanan dan kesesuaian datanya harus diuji kembali pada staging sebelum publikasi.

## Mengulang pengujian

```sh
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/qa-browser.mjs
```

Untuk browser QA, sediakan modul Playwright melalui instalasi lokal atau variabel `PLAYWRIGHT_MODULE`, dan browser terpasang melalui `QA_BROWSER_PATH` bila binary Playwright belum tersedia. Skrip menyalakan server uji pada port 3107 dengan database sementara, lalu menutup browser dan server setelah selesai. Hasil detail tersimpan di `work/qa/browser-results.json`; tangkapan layar berada di folder yang sama. File `.env` dan database sekolah tidak dipakai untuk skenario browser QA.
